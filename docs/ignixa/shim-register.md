# Ignixa Shim Register

This register tracks known compatibility shims and SDK fallbacks while Ignixa support is completed. New Firely/Ignixa bridges must be added here or removed before merge readiness.

| ID | Surface | File(s) | Allowed mode | Reason | Severity / priority | Owner / team | Planned closure | Validation |
|---|---|---|---|---|---|---|---|---|
| SHIM-PROJECTION-001 | RawResourceElement `_summary` / `_elements` output projection | `src/Microsoft.Health.Fhir.Shared.Core/Ignixa/IgnixaFhirJsonOutputFormatter.cs` | Hybrid only | Raw persisted resources do not carry Ignixa node backing, so projection still uses Firely when explicitly allowed by the fallback guard. | P1 | FHIR | Add an Ignixa-backed raw projection path or convert raw JSON to `ResourceJsonNode` before projection. | RawResourceElement projection guard tests in Ignixa and Hybrid modes. |
| SHIM-PATCH-001 | PATCH (FHIRPath PATCH and JSON Patch) | `src/Microsoft.Health.Fhir.Shared.Core/Features/Resources/Patch/` | Hybrid only | FHIRPath PATCH and JSON Patch currently depend on Firely model infrastructure, including base immutable-property checks. Strict Ignixa mode rejects these paths through the fallback guard before Firely patch processing until Ignixa-native PATCH implementations exist. Ignixa.Application prior art has FHIRPath add, replace, delete, move, and insert executors, but it depends on app-layer mutator infrastructure not present here and does not cover upsert. JSON Patch has no native Ignixa replacement identified. | P0 | FHIR | Implement Ignixa-native PATCH paths or explicitly supported adapters for FHIRPath add, replace, delete, move, insert, and upsert operations, plus JSON Patch semantics. | PATCH unit coverage verifies strict Ignixa mode rejects guarded FHIRPath PATCH and JSON Patch Firely paths and Hybrid mode preserves guarded Firely behavior; PATCH E2E coverage remains required when native Ignixa support is added. |
| SHIM-VALIDATION-001 | Resource model attribute validation fallback | `src/Microsoft.Health.Fhir.Shared.Core/Features/Validation/IgnixaResourceValidator.cs` | Hybrid only | Non-Ignixa `ResourceElement` validation and final model attribute validation still use Firely validation behavior when explicitly allowed by the fallback guard. | P0 | FHIR | Replace remaining model attribute validation fallback with Ignixa-native validation or fail fast in Ignixa mode. | Ignixa validator fallback tests in Ignixa and Hybrid modes. |

Firely and Hybrid modes explicitly use guarded Firely conformance validation instead. Other conformance resource nested cardinality remains covered by Ignixa native validation unless a failing case is identified. | P0 | FHIR | Remove supplemental checks once Ignixa validation enforces these required nested conformance fields directly. | Nested invalid conformance tests in `IgnixaResourceValidatorTests`; Hybrid fallback characterization test. |
